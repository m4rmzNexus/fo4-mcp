## Test strategy
Pure pytest, no real CK/MO2 launch — same discipline as test_tools_previs.py and test_tools_ingame_test.py (CK is long/machine-locked; these tests must run in CI in milliseconds). Build frozen Config via a local _cfg() helper; synthesize ModOrganizer.ini fixtures on tmp_path (plain base_directory, @ByteArray-wrapped, missing CreationKit entry, missing base_directory). Monkeypatch the runtime surface: ck_run._proc_running (stateful seen->gone / never / hung sequences), ck_run._kill (recorder), ck_run.time.sleep (no-op) + ck_run.time.monotonic (deterministic counter so the 180s appear_grace / deadline branches are reachable without wall-clock waits), and ctypes.windll.shell32.ShellExecuteW (fake returning >32, with a callback that reads/mutates the ini + overwrite dir to exercise the body). Assert: ini round-trip restoration in the finally (incl. on raised exception), .ckrunbak cleanup, @ByteArray unwrap, _ck_entry_index resolution, overwrite before/after diff, and the new exact-field _proc_running. Tests touch only tmp_path and the repo tree — NEVER the Steam game folder (no real CreationKit.exe is invoked; all binaries are b'MZ' stubs). No gated writes involved since nothing writes to staging/ or Data/. After the ingame_test extraction, run the whole suite to confirm _tasklist_ws_mb's existing tests still pass.
