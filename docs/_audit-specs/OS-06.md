# OS-06 — Round-trip tests fail loudly when the writer binary is absent

**verdict:** confirmed-open | **effort:** S | **risk:** low | **recommend_now:** True

**area:** record-authoring core / test infra

## What's missing
~60 of 125 tests call _skip_if_no_writer and pytest.skip when the C# binary is missing, so a CI/dev env without the built writer shows green while never exercising the authoring path. Serialization regressions in Program.cs could land unnoticed.

## Evidence (code-grounded)
CONFIRMED-OPEN. The writer is the mutagen-cli authoring CLI (tools/mutagen-cli/src/Program.cs). fo4_create_record hard-requires it and raises TOOL_BINARY_MISSING when absent (mcp-server/fo4_mcp/tools.py:2346-2352); _mutagen_cli_binary returns None when the entry is unresolved OR the .exe is missing on disk (tools.py:3683-3695). Tests dodge that by calling a duplicated _skip_if_no_writer helper that does pytest.skip("mutagen-cli not built"): defined identically in 3 files — test_tools_create_record.py:284-286, test_tools_lint_npc_template.py:56-58, test_tools_w12_handoff.py:73-75. Equivalent inline guards exist in test_tools_inspect_record.py:118-121 (_skip_if_no_mutagen_cli) and test_tools_w9_w10_bake.py:149-178. Measured counts: 61 _skip_if_no_writer() call sites across the 3 files + 12 inline "mutagen-cli not built" skips in inspect/bake, against 385 total test_ functions. The claim's "~60 of 125" matches test_tools_create_record.py specifically (125 tests, 55 writer-gated). No opt-in enforcement exists: grep for FO4MCP_REQUIRE_WRITER / REQUIRE_WRITER = 0 hits; pyproject pytest config (mcp-server/pyproject.toml:39-41) has no markers/addopts; CI runs bare `pytest -q` with the binary deliberately absent (.github/workflows/ci.yml:26-30) and CONTRIBUTING.md:31-33 documents that these "simply skip when the binary is absent." Net: a CI/dev env without the built writer is green while the entire Program.cs serialization path is never exercised — a Program.cs round-trip regression lands unnoticed. (Note: the binary IS currently built on this dev box — tools/mutagen-cli/mutagen-cli.exe dated Jun 23 — so these tests DO run locally today; the gap is the lack of any enforcement that they ran.) There is no conftest.py in mcp-server/tests/, so the 3 duplicated helpers are the natural consolidation point.

## Concrete plan

1. Add mcp-server/tests/conftest.py (none exists today). Define one shared helper require_or_skip_writer(cfg, manifest) that resolves _mutagen_cli_binary; if None, branch on os.environ.get('FO4MCP_REQUIRE_WRITER'): truthy ('1'/'true'/'yes', case-insensitive) -> pytest.fail('mutagen-cli writer not built but FO4MCP_REQUIRE_WRITER=1 demands it', pytrace=False); else pytest.skip('mutagen-cli not built'). Import _mutagen_cli_binary from fo4_mcp.tools there. Keeping the skip default preserves the pure-Python CI lane unchanged.
2. In test_tools_create_record.py:284-286, replace the body of the local _skip_if_no_writer with a call to the conftest helper (e.g. import via `from conftest import require_or_skip_writer` or expose it as a pytest fixture). Simplest non-churn option: keep each _skip_if_no_writer name but make its body delegate to the shared helper, so the 55 call sites in this file are untouched.
3. Apply the same one-line body swap to _skip_if_no_writer in test_tools_lint_npc_template.py:56-58 and test_tools_w12_handoff.py:73-75 (the other 2 duplicate definitions).
4. Apply the same to the two non-_skip_if_no_writer guards so the env flag covers the whole writer surface: _skip_if_no_mutagen_cli in test_tools_inspect_record.py:118-121, and the three inline `if _mutagen_cli_binary(...) is None: pytest.skip(...)` blocks in test_tools_w9_w10_bake.py:149-178.
5. Optionally register the flag as a pytest marker / document it in mcp-server/pyproject.toml [tool.pytest.ini_options] is not required, but add a short note to CONTRIBUTING.md:31-33 and the canonical dev loop in TASKS.md describing `FO4MCP_REQUIRE_WRITER=1 pytest -q` as the writer-enforcing run.
6. Wire it into the canonical dev loop only (NOT the existing CI pytest job, which has no binary): either (a) document the env-var run in TASKS.md/CONTRIBUTING as the local pre-commit gate, or (b) add a SEPARATE CI job that builds the writer first (dotnet publish src/Mutagen.RecordQuery.csproj -c Release -r win-x64 --self-contained false -o tools/mutagen-cli, per MANIFEST.md:307-308) then runs `FO4MCP_REQUIRE_WRITER=1 pytest -q`. Do not commit the prebuilt binary — it is GPL-3.0, gitignored, and never distributed (Karar 7).
7. Add one meta-test in conftest's home file (e.g. test_writer_enforcement.py) using monkeypatch to set _mutagen_cli_binary -> None: assert that with FO4MCP_REQUIRE_WRITER unset the helper raises Skipped, and with it set to '1' the helper raises Failed. This proves the flag flips behavior without needing the absent binary.

## Test strategy
Pure-Python, fits the existing pytest suite under mcp-server/tests/ (testpaths=["tests"], asyncio_mode=auto). The new meta-test monkeypatches fo4_mcp.tools._mutagen_cli_binary to return None (same pattern already used at test_tools_create_record.py:263 and test_tools_inspect_record.py:165) and asserts: (1) with FO4MCP_REQUIRE_WRITER unset, calling the helper raises pytest.skip (catch via pytest.raises(pytest.skip.Exception) or the outcomes.Skipped type), and (2) with monkeypatch.setenv('FO4MCP_REQUIRE_WRITER','1'), it raises Failed. No binary, no Steam folder, no FO4 install needed. Manual verification: run `pytest -q` (default — still ~73 writer tests skip cleanly when binary absent, green) and `FO4MCP_REQUIRE_WRITER=1 pytest -q` (with the locally-built mutagen-cli.exe present those tests run; with it removed they FAIL loudly instead of skipping). No writes outside the test tmp dirs / staging/; respects the safe-write boundary since no plugin authoring target changes.
