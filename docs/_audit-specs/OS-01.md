# OS-01 — WEAP (weapon) base record authoring

**verdict:** confirmed-open | **effort:** M | **risk:** low | **recommend_now:** True

**area:** record-authoring core

## What's missing
No WEAP case in the create path: no DNAM (damage/speed/reach/ammo-capacity), no model, no ammo/attack-sound FormLinks. A solo author cannot make a custom weapon at all, directly contradicting the 'quest+armor+weapon end-to-end' persona.

## Evidence (code-grounded)
The gap is real today, in BOTH layers of the create path.

C# CLI (tools/mutagen-cli/src/Program.cs):
- The create-record switch on `r.Type` spans Program.cs:1350-2645. Its cases are: object, int, float, bool, string, npc(1352), armor(1499), quest(1561), keyword(2076), formlist(2087), message(2106), book(2118), misc(2167), materialswap(2218), global(2242), faction(2290), levelednpc(2323), leveleditem(2353), cell(2383), celloverride(2420), leveleditemoverride(2477), smqn(2524), activator(2571), location(2599), locationreftype(2617), encounterzone(2624), package(2645). There is NO `weapon`/`weap` case. Grep for "Weapon|WEAP|weapon" over Program.cs returns zero matches.
- The post-write self-verification round-trip (Program.cs:2763-2808) iterates check.Armors/Books/MiscItems/Quests into a `back` dict; there is no `check.Weapons` block, so even if a weapon were authored it would not be verified.
- The Rec spec model (Program.cs:3300-3368) has armor fields (ArmorRating, BipedSlots, Armatures) and shared item fields (Value/Weight/Keywords/Model/MaterialSwap/ObjectBounds) but NO weapon-specific fields (no BaseDamage/Speed/Reach/Capacity/Ammo/AttackSound/AnimationType/Flags).

Python tool (mcp-server/fo4_mcp/tools.py):
- _CREATE_SUPPORTED_TYPES (tools.py:553-554) lists 22 types; "weapon" is absent, so fo4_create_record rejects a weapon spec before the CLI is ever invoked (validated against this tuple; rejection message at tools.py:971).
- The per-type normalizer elif-chain (tools.py:987 npc / 1145 armor / 1253 quest / 1892 book+misc / ...) has no `weapon` branch.

Mutagen API confirmed via a compiled net9 reflection probe against tools/mutagen-cli/Mutagen.Bethesda.Fallout4.dll (built+run in /tmp, cleaned up; used compiled probe per the Defender-AMSI memo, not inline reflection):
- mod.Weapons is Fallout4Group<Weapon> with AddNew(string editorId) — identical shape to mod.Armors.AddNew used at Program.cs:1501.
- Weapon exposes DNAM-equivalent stats DIRECTLY on the record (NOT a nested WeaponData subobject as in xEdit): UInt16 BaseDamage, Single Speed, Single Reach, Single MinRange, Single MaxRange, UInt16 Capacity, UInt32 Value, Single Weight.
- FormLinks: Ammo -> IFormLink<IAmmunitionGetter>; AttackSound / EquipSound / PickUpSound / PutDownSound -> IFormLink<ISoundDescriptorGetter>.
- Keywords and AttachParentSlots are ExtendedList<IFormLink<...>> (same .Add(new FormLink<...>()) pattern as armor keywords at Program.cs:1525).
- Model Model + Model FirstPersonModel + ObjectBounds ObjectBounds exist (reuse the book/misc Model + OBND code at Program.cs:2154-2163 / 2209-2214).
- Enum Weapon.AnimationTypes = HandToHandMelee|OneHandSword|OneHandDagger|OneHandAxe|OneHandMace|TwoHandSword|TwoHandAxe|Bow|Staff|Gun|Grenade|Mine (the weapon "type").
- Enum Weapon.Flag = PlayerOnly|NpcsUseAmmo|...|Automatic|...|HasScope|... (WeaponData flags; OR-able, same pattern as quest flags).

So a solo author literally cannot author a custom weapon today — confirmed-open.
