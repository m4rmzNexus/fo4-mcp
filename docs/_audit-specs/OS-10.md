# OS-10 — Crash-log detection in in-game judging + CK output validation

**verdict:** confirmed-open | **effort:** M | **risk:** low | **recommend_now:** True

**area:** in-game testing / CK automation

## What's missing
A real CTD during the post-command window makes Fallout4.exe disappear -> exited=True, so success can be reported despite a crash (the diag may have been written before the crash). The project already HAS fo4_analyze_crash_log but doesn't consult it. CK runs treat 'not hanging' as success and never assert the expected artifact was produced or scan ckpe.log for ERROR.

## Evidence (code-grounded)
IN-GAME GAP (real): mcp-server/fo4_mcp/ingame_test.py has zero crash handling (grep crash|mtime|st_mtime|glob = no matches). The run loop at lines 329-335 treats Fallout4.exe vanishing from tasklist as `exited=True` (line 332-333: `if mb is None: exited=True`) — a CTD is indistinguishable from a clean qqq exit. Success judging at lines 367-370: `success = appeared and bool(papyrus_matches)` OR `appeared and exited and sequence_completed`. So a CTD after the success_pattern was flushed to Papyrus, or after `[seq] UI: qqq` was written to diag, is reported as success. Crash logs live at cfg.fo4_user_docs/F4SE/crash-*.log (confirmed skills/fo4-crash-debug/SKILL.md:8,28; fo4_user_docs = Documents/My Games/Fallout4 per config.py:78), and the run already captures a start time implicitly (loop begins after _launch_detached at line 312).
CK GAP (real): mcp-server/fo4_mcp/ck_run.py:run_ck_via_mo2 returns overwrite_new (line 142,152) and ckpe_log_tail (line 143-145,153) but never asserts on them. Consumers reduce success to "didn't hang": previs.py:152 `all_ok = all_ok and r['exited'] and not r['timed_out']`; facegen.py:91 `ok: r['exited'] and not r['timed_out']`; seq.py:70 same pattern. No expected-artifact check, no ckpe.log ERROR scan. Tests confirm the weak contract: test_tools_previs.py:159-172 passes overwrite_new=['CombinedObjects.esp'] but asserts only on exited/timed_out.
REUSABLE: parse_crash_log (tools.py:4144, pure str->dict) and fo4_analyze_crash_log (tools.py:4241) already exist. Both gaps are fixable without touching the native plugin or launching anything new.

## Concrete plan

1. IN-GAME 1: In ingame_test.py, add module helper `_crash_dir(cfg) -> Path|None` returning `cfg.fo4_user_docs / 'F4SE'` (the proven crash-log location). Add `_newest_crash_after(crash_dir, since_epoch) -> Path|None` that globs 'crash-*.log', filters by `p.stat().st_mtime >= since_epoch - 2` (2s skew slack), and returns the newest by mtime.
2. IN-GAME 2: In fo4_run_ingame_test, just before `_launch_detached` (line 312), capture `run_start = time.time()` (and stash crash_dir). After the run/judge block (after line 365), call `crash_log = _newest_crash_after(crash_dir, run_start) if crash_dir else None`.
3. IN-GAME 3: Override the verdict: after computing `success` at lines 367-370, add `crashed = crash_log is not None`; set `success = success and not crashed`. This forces success=False whenever a fresh crash-*.log appeared during the window, regardless of papyrus_matches/sequence_completed.
4. IN-GAME 4: Surface it in the returned dict (after line 386): add `'crashed': crashed`, `'crash_log': str(crash_log) if crash_log else None`, and `'crash_summary'`: when crashed, call `parse_crash_log(crash_log.read_text(encoding='utf-8', errors='replace'))` and include a trimmed view {exception, probable_culprits[:3], verdict} (reuse the existing pure parser — import parse_crash_log lazily from .tools to avoid a heavy top-level import cycle, mirroring how previs.py imports run_ck_via_mo2 lazily).
5. CK 1: In ck_run.py, extend run_ck_via_mo2 signature with `expected_outputs: list[str] | None = None` and `failure_markers: tuple[str,...] = ('ERROR','FATAL','failed','Assert')`. After computing new_files (line 142) and tail (line 143-145): compute `missing = [e for e in (expected_outputs or []) if not any(e.lower() in nf.lower() for nf in overwrite_new_rel)]` and `log_errors = [ln for ln in full_ckpe_lines if any(m.lower() in ln.lower() for m in failure_markers)]` (read full ckpe.log lines, not just the 12-line tail, for the scan; keep tail for display).
6. CK 2: Add to the returned dict (line 146-154): `'expected_outputs': expected_outputs or []`, `'missing_outputs': missing`, `'ckpe_errors': log_errors[:20]`, and `'artifacts_ok': not missing and not log_errors`. Do NOT change `exited`/`timed_out` semantics — keep them; artifacts_ok is an additional, independent gate.
7. CK 3: In previs.py (line 151-153), facegen.py (line 88-91), seq.py (line 67-70): pass the step's expected artifact(s) as expected_outputs (e.g. previs precombined -> ['CombinedObjects.esp'], '.psg'; facegen -> the FaceGen .nif/.dds dir token; seq -> '.seq'), and fold artifacts_ok into the success: change `ok = r['exited'] and not r['timed_out']` to `ok = r['exited'] and not r['timed_out'] and r['artifacts_ok']`. Keep backward-compat default (expected_outputs=None -> missing=[] -> artifacts_ok depends only on ckpe_errors).
8. NO new MCP tool surface needed; both fo4_run_ingame_test and fo4_build_previs/facegen/seq signatures in server.py stay the same (the new fields ride existing return dicts). Honor hard rules: no writes to Steam Data (crash dir is Documents, read-only-read; ckpe.log is CK's own under the install but only READ, never written by this code).

## Test strategy
All unit, no game/CK launch — fits the existing monkeypatched pattern. IN-GAME (test_tools_ingame_test.py): extend _prep_execute/_cfg so cfg.fo4_user_docs has an F4SE subdir. (a) test_execute_crash_forces_failure: write a crash-*.log with mtime set to now into docs/F4SE/, also write a matching success_pattern to Papyrus and `[seq] UI: qqq` to diag; assert out.data.success is False, crashed is True, crash_log endswith the file, crash_summary present. (b) test_execute_stale_crash_ignored: write a crash-*.log with an OLD mtime (os.utime to run_start-3600) BEFORE the run; assert success stays True and crashed is False (proves mtime-vs-start gating, the load-bearing detail). (c) regression: existing success/failure tests must still pass with no crash dir present (crash_dir None -> crashed False). CK (test_tools_previs.py): (a) extend the existing _fake to also return artifacts_ok and assert previs ok=True when overwrite_new contains expected + no errors. (b) new test: _fake returns exited=True/timed_out=False but overwrite_new=[] (missing expected) -> data.ok False, results[0].missing_outputs non-empty. (c) new test: ckpe_log_tail/full contains 'ERROR: ...' -> artifacts_ok False -> ok False. Add a direct ck_run unit if feasible by monkeypatching _proc_running/_kill/ShellExecuteW and seeding a temp overwrite dir + ckpe.log, but the consumer-level monkeypatch tests are the minimum bar. Target: green `pytest mcp-server/tests/` (currently ~402 tests), +~6 new.
