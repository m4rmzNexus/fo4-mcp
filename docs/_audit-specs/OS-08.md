# OS-08 — COBJ (constructible) authoring + workshop recipe chain

**verdict:** confirmed-open | **effort:** M | **risk:** low | **recommend_now:** True

**area:** record-authoring core / crafting

## What's missing
AObjectModification (OMOD) and ConstructibleObject (COBJ) are not authorable, so chem/cooking/workshop recipes and the planned settlement display-board cannot be created. COBJ is the tractable half (reuses BuildCondition); OMOD's property-modifier list is a complex binary struct.

## Evidence (code-grounded)
COBJ is genuinely unimplemented today. (1) The create-dispatch switch at tools/mutagen-cli/src/Program.cs:1350 (switch on r.Type) has cases for npc/armor/quest/keyword/formlist/message/global/faction/levelednpc/leveleditem/leveleditemoverride/cell/celloverride/smqn/activator/location/encounterzone/package/book/misc/materialswap but NO constructibleobject/cobj case; the default at Program.cs:2708 returns Fail("unsupported record type"). (2) The Python allowlist _CREATE_SUPPORTED_TYPES at mcp-server/fo4_mcp/tools.py:554 omits it, so a "ConstructibleObject" record is rejected at tools.py:970 before reaching the CLI. (3) Explicitly tracked-not-built: docs/V2-backlog.md:464 ("workshop STAT->COBJ buildables") and docs/world-content-quest-roadmap.md references. (4) The reuse claim holds: BuildCondition (Program.cs:927) returns ConditionFloat (a Condition) and is already shared by 8 record types (smqn at Program.cs:2557, scenes, packages, etc.) — it drops straight into COBJ's Conditions list. (5) Authoritative Mutagen 0.53.1 API confirmed via compiled reflection probe against tools/mutagen-cli/Mutagen.Bethesda.Fallout4.dll: mod.ConstructibleObjects.AddNew(eid) (concrete record, like book at Program.cs:2127); fields = CreatedObject (IFormLinkNullable), CreatedObjectCounts (ExtendedList<ConstructibleCreatedObjectCount{Count:UInt16, Priority:UInt16}>), Components (ExtendedList<ConstructibleObjectComponent{Component:IFormLink, Count:UInt32}>), Conditions (List<Condition>), WorkbenchKeyword (IFormLinkNullable<IKeyword>), Categories (ExtendedList<IFormLinkGetter<IKeyword>>), MenuArtObject (IFormLinkNullable), PickUpSound/PutDownSound. PROPOSAL CORRECTIONS: menu art property is MenuArtObject not "MenuArt"; the created-object count is a list (CreatedObjectCounts) not a scalar; and critically the recipe-menu "categories" are KEYWORD FormLinks (Categories: List<IFormLinkGetter<IKeyword>>) NOT an FLST — the proposed "FLST workshop menu categories + CategoryKeyword" is wrong (CategoryKeyword does not exist in the API). OMOD half is correctly identified as separate/complex and stays a research gate.

## Blockers / scope notes
None for the COBJ half. It is fully autonomous: no GUI, no user decision, no credential — same Mutagen-writer + pytest round-trip harness already proven for 22 record types. The C# API is confirmed by a compiled reflection probe (all setters exist: CreatedObject/CreatedObjectCounts/WorkbenchKeyword/Categories/Components/Conditions/MenuArtObject). The only caveat is naming: implement against MenuArtObject (not MenuArt), CreatedObjectCounts list (not a scalar), and Categories as keyword FormLinks (NOT an FLST/CategoryKeyword as the proposal stated). In-game workshop-mode validation is a nice-to-have follow-up but not required to ship the writer (disk round-trip + Spriggit 2nd-engine is the established green bar). OMOD is correctly deferred — it is the one genuinely-hard part (binary property-modifier value-union) and must stay a separate research-gated item, not bundled into this build.
